§ 03 — ML Algorithms

Three learners, three markets.

A transformer for direction, a state-space filter for spreads, and a multi-agent policy for crypto — each sized to its market, each tested walk-forward.

Model 01 · Meridian.AI — forex & stocks

A small model
that had to learn.

Meridian is a 430k-parameter transformer for financial time series — grouped-query attention, rotary positions, a two-expert mixture with top-2 routing, and a loss that trains price and direction together. An 11M-parameter version collapsed onto a constant prediction; the smaller network has to find real signal to reduce the loss.

It retrains hourly on a CPU GitHub Actions runner and publishes each checkpoint to Hugging Face. A sanity gate blocks a degenerate model from ever shipping.

Where those numbers come from
Method, not marketing

A directional accuracy figure is only meaningful next to the protocol that produced it. Every number on this page comes from the same walk-forward test, scored against the naïve baseline it has to beat.

01 · The test
Walk-forward

Pick a random historical date. Give the model only what existed up to that date, ask for the next day's move, compare the sign to what actually happened. Repeat.

02 · No lookahead
Strictly causal

Every one of the 44 features is backward-looking and the target is strictly in the future. Training splits 80/20 chronologically — validation is always the most recent slice, never a shuffled sample.

03 · The baseline
Always-up

Markets drift up, so guessing "up" every day already scores 51.7% on FX and 51.5% on equities. Edge is accuracy minus that baseline — not accuracy minus fifty.

04 · The test statistic
z-score vs baseline

A one-proportion test asks whether the gap could be luck. z = 8.4 on 960 FX predictions is not luck. z = 1.3 on 1,680 equity predictions is indistinguishable from it.

What is being optimised
loss = 0.6·Huber + 0.4·weightedBCE

Price error and direction error are trained together, which is why the direction signal falls out of the same forward pass. Features are z-scored on training statistics and clamped to [-10, 10].

Why to trust the pipeline

Before publishing, a sanity gate runs each fresh checkpoint over held-out windows and looks for the failure signatures of a broken model: a constant output, a collapse onto one direction, or a blown-up prediction scale. A degenerate checkpoint is deleted instead of pushed and the run is marked failed.

This gate exists because pre-1.0 versions reported far higher training accuracy while performing near chance live — a contaminated pipeline had let the model collapse onto a near-constant prediction.

Model 02 · Prophet × Kalman — pair trading

The spread,
not the forecast.

The pair-trading desk hunts for pairs that move together in a way that is statistically hard to fake: Engle–Granger cointegration over every pair in the sector — train window only, correlation floor, Benjamini–Hochberg false-discovery control — then an ADF test on the OLS hedge-ratio spread.

The trade signal is a Kalman filter that re-estimates the hedge ratio every bar and standardises the residual into a z-score. Prophet fits a grid-searched 365-day projection for each leg, but it stays a projection: no forecast price ever reaches the trade loop, because P&L computed on forecasted prices is not real performance.

Model 03 · MAPPO-LSTM — crypto

Three agents,
one critic.

One reinforcement-learning agent per market — BTC/USD, ETH/USD and ETH/BTC — each an LSTM actor that sees only its own pair. A single centralised critic watches all three at once: centralised training, decentralised execution.

Training is PPO with clipped ratios and GAE; each step's reward is P&L as a fraction of the agent's $10,000 book, so rewards, values and returns share one scale. Walk-forward folds retrain from scratch and keep the best-on-validation checkpoint — the one the live Alpaca desk actually loads.
