> Reads the filings and ratios for both legs of the active pair, then commits to a direction — and names the option structure that expresses it.

Scrapes and normalises fundamentals, computes the ratio set, and asks a local LLM for a directional verdict per leg. The verdict is what unlocks the Bull Call or Bear Put desk in the hub.

### The handoff that matters

This desk writes `report_stock1.json` and `report_stock2.json`. The hub reads
them (`suggested_tabs()` in `main.py` on the `hub` branch) and uses the
`option_strategy.name` field to decide which strategy desks to unlock:

- both legs bearish → **Bear Put** only
- one bullish, one bearish → **both** desks

The name is free-form LLM text, so matching is on keyword pairs — `"Bear Put
Debit Spread"`, `"bear put spread"` and `"BEAR PUT"` all resolve identically.

### Data

`yfinance` for prices and statements, `requests` + `BeautifulSoup` for filings
that yfinance does not carry, `ollama` for the written verdict.

<details>
<summary><b>Running this desk</b></summary>

<br>

These are [marimo](https://marimo.io) notebooks, not scripts. Each one is a
reactive dashboard: cells re-execute when their inputs change, so there is no
hidden run order to remember.

```bash
pip install marimo
marimo run fundamental.py          # read-only dashboard
marimo edit fundamental.py         # editable notebook
```

Served together, all desks live behind one FastAPI hub with a password gate
(branch [`hub`](../../tree/hub)). Credentials come from a local `.env` that is
never committed -- see `.env.example` on the `hub` branch for the variable
names.

</details>

<details>
<summary><b>Honest limitations</b></summary>

<br>

The verdict is generated by a language model reading summarised fundamentals. It is a starting hypothesis, not a recommendation, and it will produce a confident-sounding answer even when the underlying data is thin or stale. Scrapers break when source layouts change.

</details>
